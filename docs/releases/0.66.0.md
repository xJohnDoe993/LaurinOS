# PaimenOS 0.66.0

Diese Version enthält die Änderungen aus Pull Request #37 und #38.

## Offene Arbeiten bei abgelaufener Bildschirmzeit erhalten

- Der Sperrbildschirm fährt das Gerät nicht mehr nach zehn Minuten automatisch herunter. Ausschalten erfordert eine Bestätigung.
- Offene Apps bleiben erhalten. Eltern können zusätzliche Zeit zum Fortsetzen oder Speichern freigeben.
- RetroArch erhält einen Speicherauftrag über eine private stdin-Pipe und wird nach zwei Sekunden angehalten. Bonuszeit setzt dieselbe Sitzung fort.
- Automatische Speicherplatznummerierung und regelmäßiges SRAM-Speichern sind aktiviert. Ein Speicherauftrag ist keine bestätigte Sicherung: Nicht unterstützte Cores oder Schreibfehler bleiben möglich. Die laufende Sitzung bleibt deshalb im RAM erhalten; Ausschalten verliert diesen Zustand.

## Sperre bei beschädigten Einstellungen erhalten

- Ungültige oder fehlende Zeitwerte werden nicht mehr still in null umgewandelt. Dadurch kann ein beschädigtes Tageslimit keine unbegrenzte Nutzung freigeben.
- Zeitwächter und Sperrbildschirm bleiben bei Datenfehlern aktiv. Ein sichtbares Kindermenü wird ausgeblendet.
- Nach einer gültigen Reparatur mit verfügbarer Zeit wird die Sperre wieder aufgehoben. Nach Fehlern im PIN-/Bonusdialog wird die Aktualisierung zuverlässig fortgesetzt, ohne das automatische Herunterfahren wieder einzuführen.

## Aktualisieren

Von Version 0.65.0 ist das vollständige Update über das Elternbackend möglich. Paket-API bleibt **3**. Alternativ `PaimenOS-0.66.0.zip` entpacken und im Projektordner ausführen:

```bash
bash update.sh --check
sudo bash update.sh
```

Von Paket-API 2 ist dieses vollständige manuelle Update erforderlich; kein Teilupdate verwenden. Alte LaurinOS-Installationen benötigen weiterhin eine Neuinstallation. Eltern-Einstellungen, Apps und gespeicherte Daten bleiben erhalten. Laufende Arbeiten vor dem Update speichern, da Dienste neu gestartet werden.

## Prüfung und Grenzen

Die zusammengeführten Änderungen werden durch die Projektprüfungen einschließlich Qt-/Flask-Tests und Emulator-Sitzungstests geprüft. Die Konfliktauflösung erhält sowohl den Schutz bei beschädigten Einstellungen als auch den Verzicht auf automatisches Herunterfahren. Der Release-Workflow prüft zusätzlich echte X11-Videowiedergabe und erzeugt ZIP sowie SHA-256.

Kein echter RetroArch-Core-, Debian-Installations- oder Hardwaretest wurde lokal durchgeführt. Details: `docs/screen-time-preservation.md` und `docs/project-review-2026-10-09.md` (historischer Prüfbericht vor der Zusammenführung).
